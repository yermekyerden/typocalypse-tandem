# Date: 2026-03-20

## Что было сделано
- Продолжил работу над backend для модулей и терминала, чтобы обучение проходило не через моки, а через реальные API и backend runtime.
- Сделал создание terminal attempt по `lessonId`, чтобы backend сам понимал, какой сценарий запускать для выбранного урока.
- Добавил runtime для всех 4 модулей: `Command Line Basics`, `File System Paths`, `Permissions`, `Working with Files`.
- Убрал временную связку на фронте между уроком и mission, потому что теперь это определяется на backend.
- Доработал terminal engine: добавил поддержку команд с `&&`, `chmod`, `wc -l`, `ls -l`, а также проверку прав доступа для `cat`.
- Исправил проблему с `echo`, из-за которой в файл записывался не тот текст.
- Прогнал тесты и сборку backend после основных изменений.

## Контекст / Примечания
- По ходу работы стало понятно, что проблема была не только во фронте, а в том, что backend не связывал урок и terminal scenario нормально. Из-за этого текст задания мог быть один, а backend ждал вообще другую команду.
- Поэтому я решил идти по шагам: сначала довел до ума первый модуль, потом второй, потом уже доработал engine для более сложных вещей в `Permissions` и `Working with Files`.
- Отдельно пришлось разбираться с `echo`, потому что внешне команда была правильная, но backend записывал в файл не тот текст. После проверки стало понятно, что ошибка была в обработке аргументов команды.
- Для модуля `Permissions` пришлось добавить более реальную логику прав доступа, иначе этот модуль нельзя было бы нормально пройти через backend.
- Во время интеграции и синхронизации frontend с backend я использовал Postman, чтобы получить токен и дальше использовать его в разработке и проверке задачи. На тот момент на фронте еще не была готова регистрация и авторизация, поэтому без этого нормально тестировать API и terminal flow не получалось.
